[[data-protection]]
== Datenschutz

[cols="30%,70%"]
|===
| Aktualisieren | Beschreibung 


 a| 
xref:../data-protection/cloud-backup-with-snapmirror-task.html[SnapMirror cloud support für die Wiederherstellung vor Ort auf dem ursprünglichen Quell-Volume]
 a| 
SnapMirror cloud unterstützt Wiederherstellungsvorgänge vor Ort für FlexVol Volumes, sodass Sie eine Cloud-Snapshot-Wiederherstellung direkt auf dem ursprünglichen Quell-Volume durchführen können. ONTAP wählt den neuesten gemeinsamen Snapshot aus und führt eine inkrementelle Übertragung durch, wodurch sich die Wiederherstellungszeit verkürzt.



 a| 
xref:../snapmirror-active-sync/limits-reference.html[Erhöhte Grenzwerte für SnapMirror active sync Objekte]
 a| 
SnapMirror active sync erhöht die Anzahl der pro HA-Paar unterstützten Volumes bei SAN- und NAS-Konfigurationen auf 600.



 a| 
xref:../snaplock/snapshot-lock-concept.html[Manipulationssichere Snapshot-Unterstützung mit SnapMirror active sync NAS]
 a| 
ONTAP bietet nun Unterstützung für manipulationssichere Snapshots mit SnapMirror active sync NAS FlexVol Volumes. Diese Erweiterung ermöglicht Kunden, die NAS Verfügbarkeit von SnapMirror active sync mit dem Schutz unveränderlicher Snapshots zu kombinieren.



 a| 
xref:../data-protection/modify-svm-dr-dest-vol-capacity-task.html[Erweiterte SVM Disaster Recovery]
 a| 
ONTAP verbessert die SVM-Notfallwiederherstellung, indem es die Änderung ausgewählter Attribute mit volume modify auf SVM-DR-Ziel-Volumes mithilfe von Standard-Workflows für volume modify mit Administratorrechten ermöglicht und so den Bedarf an vom Support unterstützten Verfahren reduziert.

ONTAP erweitert außerdem die optionale SVM-DR Quick Resync-Unterstützung auf FlexGroup Komponenten und hilft großen SVMs mit FlexGroup, nach DR-Probe-, Resync- oder Flip-Resync-Workflows schneller wieder in einen geschützten Zustand zurückzukehren.

Weitere Informationen finden Sie unter xref:../data-protection/resync-svm-destination-task.html[Die Daten auf einer ONTAP SnapMirror Ziel-SVM werden erneut synchronisiert].



 a| 
xref:../data-protection/configure-backend-fc-replication.html[Backend-Unterstützung für die SnapMirror Replizierung über FC]
 a| 
Sie können die asynchrone Backend-Replizierung von SnapMirror und SnapLock für SnapVault über vorhandene Fibre Channel (FC) Fabrics konfigurieren.

Dadurch kann der Replikationsverkehr vollständig innerhalb der bestehenden SAN-Infrastruktur abgewickelt werden. Vor ONTAP 9.20.1 wurde der Verkehr für diese Replikationsbeziehungen ausschließlich über das Intercluster-IP-Netzwerk übertragen.



 a| 
xref:../consistency-groups/protect-task.html[Replikation von einer Nicht-SnapLock Quell-Konsistenzgruppe zu einer SnapLock für SnapVault Ziel-Konsistenzgruppe]
 a| 
Sie können von einer Nicht-SnapLock Quell-Konsistenzgruppe zu einer SnapLock für SnapVault Ziel-Konsistenzgruppe replizieren. SnapLock für SnapVault schützt die replizierten Konsistenzgruppen vor versehentlichem oder böswilligem Löschen.



 a| 
xref:../san-admin/fc-sp-3-security-support.html[FC-SP-3 Authentifizierung und Verschlüsselung mit sicheren Broadcom HBAs]
 a| 
ONTAP unterstützt Authentifizierung und Verschlüsselung gemäß Fibre Channel Security Protocol 3 (FC-SP-3) auf sicheren Broadcom HBAs mit AFF und FAS Systemen. Die FC-SP-3-Unterstützung ermöglicht End-to-End-Verschlüsselung auf Hardwareebene und Geräteauthentifizierung zum Schutz von Daten auf der Übertragungsstrecke zwischen FC- und NVMe/FC-SAN-Hosts und ONTAP Storage-Systemen und entspricht gleichzeitig den T11 Fibre Channel Sicherheitsstandards.

Die Verschlüsselung wird ausgelagert, sodass es keine Auswirkungen auf die Performance Ihres Storage-Systems gibt.

 a|

FPolicy erweitert die Dateizugriffsüberwachung auf NFSv4.2 und ermöglicht so Audit-, Compliance- und Cyberresilienz-Workflows für Umgebungen mit der neuesten NFS-Protokollversion. Diese Funktion bietet eine unterbrechungsfreie Überwachung ohne Auswirkungen auf die Performance.

[[nas]]
== NAS

[cols="30%,70%"]
|===
| Aktualisieren | Beschreibung 


 a| 
xref:../smb-admin/supported-versions-functionality-concept.html[SMB-Unterstützung für normalisierte Namensabfragen für Windows Clients]
 a| 
Windows-Clients können kanonische Datei- und Verzeichnisnamen in einer einzigen Anfrage abrufen. Dies reduziert die Latenz beim Öffnen von Dateien und verbessert die SMB-Kompatibilität für Unternehmens-Desktops, Anwendungen und Dateiserver. ONTAP gibt automatisch kanonische Pfade für geöffnete Dateien und Verzeichnisse zurück und vermeidet so komponentenbezogene Suchvorgänge auf Windows 11 24H2 und späteren Clients ohne zusätzliche Konfiguration.



 a| 
xref:../nfs-admin/support-vmware-vstorage-over-nfs-concept.html[Automatische Speicherplatzrückgewinnung für VMware NFS-Datenspeicher]
 a| 
ONTAP unterstützt die automatische Speicherplatzrückgewinnung für NFS-Datenspeicher über das NetApp NFS Plug-in für VMware VAAI. Dies trägt dazu bei, Speicherplatz aus Thin-Provisioning-VMDK-Blockbereichen freizugeben, wenn Hosts mit VMware ESXi 9.0 oder höher UNMAP-Operationen ausführen.



 a| 
xref:../volumes/cautions-increasing-maximum-directory-size-concept.html[Maximale Verzeichnisgröße für ONTAP FlexVol Volumes]
 a| 
ONTAP verbessert die Performance sehr großer Verzeichnisse mit bis zu ca. 25 Millionen Dateien, indem Verzeichnisgrößen bis zu 4 GB unterstützt werden. Kunden mit Workloads, die extrem hohe Dateianzahlen in einem einzelnen Verzeichnis erzeugen, wie z. B. KI-Training, profitieren davon, dass die zuvor bei großen Verzeichnissen auftretenden Performanceeinbußen vermieden werden. Zudem verbessert ONTAP die Ausfallsicherheit, indem sichergestellt wird, dass Verzeichnisse nach einem Data Protection Failover vollständig indiziert bleiben, sodass replizierte Kopien auch dann eine gute Performance bieten, wenn eine SnapMirror Beziehung unterbrochen ist. Diese Funktion ist mit AFF und FAS Storage-Systemen einschließlich MetroCluster Bereitstellungen verfügbar; sie kann bei Bedarf auf jedem Volume aktiviert werden.



 a| 
xref:../task_nas_provide_client_access_with_name_services.html[Unterstützung für die automatische Konvertierung von SID zu UNIX-ID]
 a| 
ONTAP führt die Unterstützung für die automatische Konvertierung von SIDs in UNIX-IDs für LDAP-verbundene SVMs ein, um POSIX-UIDs/GIDs aus Windows-SIDs zu generieren und zurückzukonvertieren. Dadurch entfällt die Notwendigkeit, die Attribute uidNumber/gidNumber in Active Directory manuell zu pflegen, was den Verwaltungsaufwand reduziert und zu einem konsistenten Dateizugriff über NFS und SMB beiträgt. Diese branchenkonforme Funktion ist besonders wertvoll für Kunden, die große Netzwerke von SSSD-basierten NAS-Plattformen migrieren und die Konsistenz der Identitätszuordnung beibehalten möchten. Die Funktion ist standardmäßig deaktiviert und wird pro SVM konfiguriert.

[[security]]
== Sicherheit

[cols="30%,70%"]
|===
| Aktualisieren | Beschreibung 


 a| 
Apache Fair Queueing für Überlastungen bei Management-Verbindungen und Precluster-Erweiterungen
 a| 
ONTAP führt auf dem Management-Webserver ein optionales, standardmäßig deaktiviertes Fair Queueing nach Quell-IP ein, um den Zugriff auf REST, System Manager und ONTAPI auch bei einem hohen Aufkommen an Management-Verbindungen aufrechtzuerhalten. ONTAP unterstützt zudem die Image-Installation über eine ausschließlich vor der Cluster-Einrichtung verfügbare REST API und verbessert die DHCP-Verarbeitung, sodass die Pre-Cluster-Knotenverwaltungs-LIF auch bei Lease-Verlängerungen und IP-Adressänderungen verfügbar bleibt, während der Knoten auf die Cluster-Einrichtung wartet.



 a| 
xref:../anti-ransomware/modify-snapshot-options-arpai.html[Erweiterte Steuerungsmöglichkeiten für ARP/AI-Snapshot-Antwortrichtlinien]
 a| 
Die ARP/AI Snapshot-Antwortrichtlinie kann auf SVM- oder Volume-Level konfiguriert werden, um zu steuern, ob ARP/AI bei Erkennung ungewöhnlicher Aktivität Snapshots erstellt. Drei Richtlinien sind verfügbar: `alert-with-proactive-and-periodic-snapshot` (Standard, bisheriges Verhalten wird beibehalten), `alert-with-proactive-snapshot` (nur Angriffs-Snapshots, keine periodischen Snapshots) und `alert-only` (nur Warnungen und Ereignisprotokolle, es werden keine Snapshots erstellt). Nach einem Upgrade auf 9.20.1 ändert sich die standardmäßige maximale Anzahl periodischer Snapshots von 6 auf 2, und der standardmäßige Aufbewahrungszeitraum ändert sich von 12 auf 7 Stunden, sofern diese Optionen auf Knotenebene nicht zuvor geändert wurden.



 a| 
xref:../encryption-at-rest/enable-external-key-management-96-later-nve-task.html[Verbesserungen des Schlüsselverwaltungs-Workflows für Daten-SVMs]
 a| 
Wenn Sie einen externen Schlüsselmanager auf einer Daten-SVM aktivieren, kann ONTAP die Volume-Verschlüsselungsschlüssel dieser SVM automatisch vom Schlüsselmanager im Admin-Bereich zum neuen Daten-SVM-Schlüsselmanager migrieren. Dies vereinfacht den Übergang zur externen Schlüsselverwaltung und macht einen separaten manuellen Migrationsschritt im Standard-Workflow überflüssig.



 a| 
xref:../multi-admin-verify/index.html[Unterstützung für IdP-, AD- und LDAP-Gruppen als MAV-Genehmiger]
 a| 
MAV-Genehmigungsgruppen können neben einzelnen Administratoren auch Gruppen von Identity Provider (IdP), Active Directory (AD) und LDAP (nsswitch) als Genehmiger umfassen. Unterstützte Gruppentypen sind Entra ID, ADFS, AD-Domänengruppen und LDAP-Gruppen. Das Hinzufügen oder Entfernen von Benutzern im IdP-, AD- oder LDAP-Verzeichnis erfordert keine Änderungen an der MAV-Konfiguration. Änderungen an der Gruppenzugehörigkeit eines Benutzers werden nach einer erneuten Authentifizierung bei der nächsten Anmeldung des Benutzers wirksam. Mit dem Befehl security multi-admin-verify registered-operations show lassen sich alle MAV-geschützten Vorgänge anzeigen, die auf dem aktuellen Cluster verfügbar sind.



 a| 
xref:../networking/configure_snmpv3_users_in_a_cluster.html[Unterstützung für die SNMPv3 SHA-512 Authentifizierung]
 a| 
ONTAP unterstützt die SHA-512-Authentifizierung für SNMPv3-Benutzer. Diese Erweiterung ermöglicht die Verwendung einer stärkeren SNMPv3-Authentifizierung für externe SNMP-Clients und für die Switch-Überwachung, einschließlich Switches, die eine SHA-512-Authentifizierung erfordern. Weitere Informationen finden Sie unter „Configure SNMPv3 users in an ONTAP cluster“ und „Configure SNMPv3 for Ethernet switch health monitoring“.

Weitere Informationen sind unter  https://docs.netapp.com/us-en/ontap-systems-switches/switch-cshm/config-snmpv3.html["SNMPv3 für die Zustandsüberwachung von Ethernet-Switches konfigurieren"] zu finden.

[[storage-efficiency-enhancements]]
== Verbesserungen der Storage-Effizienz

[cols="30%,70%"]
|===
| Aktualisieren | Beschreibung 


 a| 
xref:../concepts/capacity-measurements.html[Vereinfachte Berichterstattung über Datenreduzierungsraten der Storage-Effizienz]
 a| 
Die Datenreduktionsrate (DRR) der Storage Effizienz ermöglicht eine präzisere Bewertung der ONTAP Storage Speicherplatzeinsparungen, da nur reduzierbare Daten berücksichtigt werden. In ONTAP 9.19.1 und früheren Versionen umfasst die DRR sowohl reduzierbare als auch nicht reduzierbare Daten.



 a| 
xref:../concepts/builtin-storage-efficiency-concept.html[Verbesserte Performance nach der Migration von Volumes von Nicht-QAT-Systemen auf QAT-Systeme]
 a| 
ONTAP reduziert zusätzliche Leselatenz und CPU-Auslastung, die nach der Migration von Volumes von Systemen, die QuickAssist Technology (QAT) nicht unterstützen, auf Systeme, die sie unterstützen, auftreten können.



 a| 
Optimierung des automatischen Deduplizierungsplaners (ADS)
 a| 
ONTAP verbessert die Performance von ADS (Automatic Dedupe Scheduler) und ermöglicht dadurch mehr gleichzeitige Deduplizierungssitzungen pro Knoten sowie eine intelligentere und gezieltere Drosselung, um Client-I/O besser auszubalancieren. Die Deduplizierungsaktivität auf DP Volumes (aus SnapMirror Transfers) und globale Deduplizierungssitzungen werden zusammen mit der regulären Volume-Deduplizierung verwaltet, wodurch Konflikte und das Wachstum von Metadaten reduziert werden. Dadurch ergeben sich Einsparungen bei der Storage-Effizienz, insbesondere bei gemischten Workloads, ohne dass Konfigurationsänderungen erforderlich sind. Diese Funktion ist standardmäßig aktiviert und auf AFF Storage-Systemen verfügbar.

 a| 
xref:../flexcache/supported-unsupported-features-concept.html[NVFail-Unterstützung mit FlexCache]

Sie können FlexCache Beziehungen mit NVFAIL-fähigen Ursprüngen erstellen. NVFAIL lässt sich auch auf Cache-Volumes unabhängig von Ursprungsvolumes aktivieren. Auf Ursprungs- oder Cache-Volumes, auf denen NVFAIL aufgetreten ist, blockiert ONTAP Datenlesevorgänge oder Änderungen, während das Zurückschreiben geänderter zwischengespeicherter Daten erhalten bleibt, und der normale E/A-Betrieb wird nach der Wiederherstellung fortgesetzt.



 a| 
Leistungsverbesserung für asynchrones Löschen
 a| 
ONTAP verbessert die Performance bei asynchronem Löschen und beschleunigt die Speicherplatzrückgewinnung für NAS/SMB-Clients. Einzelheiten erhalten Sie bei Ihrem NetApp Ansprechpartner.



 a| 
xref:../data-protection/calculate-reclaimable-space-task.html[Unterstützung für die Berechnung des zurückgewinnbaren Speicherplatzes auf FlexGroup Volumes]
 a| 
ONTAP unterstützt die Neuberechnung des wiederverwendbaren Speicherplatzes vor dem Löschen von Snapshots auf FlexGroup Volumes.



 a| 
xref:../flexgroup/provision-automatically-task.html[Automatische Provisionierung von Hochleistungs-FlexGroup Volumes]
 a| 
ONTAP vereinfacht die FlexGroup Provisionierung mit Storage-Profilen, mit denen Kunden für ihre Workloads einen ausgewogenen oder Performance-starken Datencontainer auswählen können, wodurch Administratoren die einzelnen Volumes seltener manuell konfigurieren und dimensionieren müssen, um die Performance-Anforderungen zu erfüllen.



 a| 
xref:../flexgroup/enable-adv-capacity-flexgroup-task.html[SMB Multichannel-Unterstützung mit erweiterter Kapazitätsneuausrichtung]
 a| 
ONTAP unterstützt die Verwendung von SMB Multichannel, wenn die erweiterte Kapazitätsverteilung auf FlexGroup Volumes aktiviert ist.



 a| 
xref:../svm-migrate/index.html#supported-and-unsupported-features[Unterstützung der SVM Migration für S3 NAS-Buckets]
 a| 
ONTAP unterstützt die SVM-Migration für SVMs, die S3-NAS-Buckets auf FlexVol Volumes hosten, sodass Administratoren SVMs migrieren können, ohne vorher die S3-NAS-Konfiguration entfernen zu müssen.



 a| 
xref:../task_nas_file_system_analytics_view.html[File System Analytics Beibehaltung der Zugriffszeit]
 a| 
Die Scans von File System Analytics und das Durchsuchen im System Manager File System Explorer erhalten die Metadaten zur Verzeichniszugriffszeit (atime). Dies trägt dazu bei, genaue atime-Werte für Archivierung, Tiering, Compliance und Datenlebenszyklus-Workflows zu gewährleisten.



 a| 
xref:../volumes/manage-svm-capacity.html[MetroCluster IP-Unterstützung für Kapazitätsgrenzen von ONTAP SVM]
 a| 
Sie können Storage-Beschränkungen für SVMs konfigurieren, die Teil einer MetroCluster IP-Konfiguration sind.



 a| 
FlexCache Volumenkennzahlen
 a| 
FlexCache Volumenmetriken melden die Menge an Daten und Metadaten, die zwischen einem FlexCache Volume und seinem Ursprungs-Volume ausgetauscht werden. Den vorhandenen ONTAP REST Endpunkten für Volumenstatistiken und -metriken wurden zwei neue Eigenschaften hinzugefügt, die Transparenz in den Datentransfer von FlexCache zum Ursprung und vom Ursprung zu FlexCache bieten. Die Zähler werden automatisch erfasst, ohne dass eine Konfiguration erforderlich ist; sie sind hilfreich für die Kapazitätsplanung, Performance Analyse, Netzwerk-Fehlerbehebung und Chargeback-Analysen. Diese Funktion erfordert ONTAP 9.20 oder höher sowohl auf den FlexCache als auch auf den Ursprungsknoten. Weitere Informationen enthält die link:https://docs.netapp.com/us-en/ontap-automation["ONTAP Automatisierung"^] Dokumentation.



 a| 
Neuausgleich innerhalb des Clusters
 a| 
ONTAP führt zwei neue Funktionen für die ausgewogene Platzierung ein, die dazu beitragen, dass Cluster mit minimalem Verwaltungsaufwand optimal arbeiten, auch wenn sich Ihre Workloads und Clusterkapazitäten weiterentwickeln. Mit der Platzierungssteuerung zum Zeitpunkt der Provisionierung können Kunden über die REST API angeben, ob beim Platzieren eines neuen Volumes Performance- oder Speicherplatzanforderungen priorisiert werden sollen. Space Performance Rebalance (SPR) ist ein Hintergrundprozess, der kontinuierlich nach sich entwickelnden Performance-Hotspots oder Platzmangel in Aggregaten im gesamten Cluster sucht. Je nach konfiguriertem Modus empfiehlt SPR entweder korrigierende Volume-Verschiebungen über EMS-Benachrichtigungen oder führt diese mithilfe standardmäßiger und unterbrechungsfreier ONTAP Volume-Verschiebungsvorgänge automatisch durch. Weitere Informationen enthält die link:https://docs.netapp.com/us-en/ontap-automation["ONTAP Automatisierung"^] Dokumentation.
