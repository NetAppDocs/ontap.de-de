= Unterstützte Dateioperationen- und Filterkombinationen, die ONTAP FPolicy für S3 überwacht
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Bei der Konfiguration Ihres FPolicy-Ereignisses ist zu beachten, dass für die Überwachung von S3-Objektzugriffsvorgängen nur bestimmte Kombinationen von Dateivorgängen und Filtern unterstützt werden.

Ab ONTAP 9.20.1 unterstützt FPolicy Benachrichtigungen für S3-Objektereignisse auf NAS-Buckets. S3 FPolicy arbeitet ausschließlich im asynchronen, nicht obligatorischen Modus.

Die Liste der unterstützten Dateivorgänge und Filterkombinationen für die FPolicy Überwachung von S3-Objektzugriffsereignissen ist in der folgenden Tabelle aufgeführt:

[cols="30,70"]
|===


| Unterstützte Dateivorgänge | Unterstützte Filter 


 a| 
object_create
 a| 
object-create-with-put, object-create-with-copy, object-create-with-complete-mpu



 a| 
object_delete
 a| 
exclude-multi-delete



 a| 
object_tag
 a| 
object-tag-put, object-tag-delete

|===


[[filter-descriptions]]
== Filterbeschreibungen

Die folgende Liste beschreibt jeden S3 FPolicy-Filter:

* object-create-with-put: Überwachung von Objekterstellungsvorgängen, die mithilfe einer PUT-Anfrage durchgeführt werden.
* object-create-with-copy: Überwachung von Objekterstellungsvorgängen, die mit einer COPY-Anforderung durchgeführt werden.
* object-create-with-complete-mpu: Überwachung von Objekterstellungsvorgängen, die durch das Abschließen eines Multipart-Uploads ausgeführt werden.
* Mehrfachlöschung ausschließen: Benachrichtigungen für Objekte, die im Rahmen einer Mehrfachlöschungsanforderung gelöscht wurden, werden ausgeschlossen. Wenn dieser Filter aktiviert ist, generiert FPolicy nur Benachrichtigungen für Löschvorgänge einzelner Objekte.
* object-tag-put: Überwachung von Vorgängen, die ein Objekt-Tag hinzufügen oder ändern.
* object-tag-delete: Überwachung von Vorgängen, die ein Objekt-Tag entfernen.




[[additional-considerations-for-s3-fpolicy-events]]
== Zusätzliche Überlegungen zu S3 FPolicy Ereignissen

* Nur erfolgreiche, clientgesteuerte S3-Operationen generieren FPolicy-Benachrichtigungen. Intern generierte Operationen (wie z. B. Objektablauf oder Snapshot-Wiederherstellung) und fehlgeschlagene Operationen generieren keine Benachrichtigungen.
* GET-Operationen (Lesen) werden für die S3 FPolicy Überwachung nicht unterstützt.
* Eine Mehrfachlöschanforderung kann bis zu 1.000 Objekte löschen. FPolicy generiert für jedes erfolgreich gelöschte Objekt eine Benachrichtigung. Jede Benachrichtigung innerhalb derselben Mehrfachlöschanforderung verwendet dieselbe FPolicy Anforderungs-ID und S3 Anforderungs-ID zur Korrelation.
* Benachrichtigungen über verweigerten Zugriff werden für S3-Ereignisse nicht unterstützt.
